# Cendana Studio project guidelines

These project-specific rules are composed into CLAUDE.md by Laravel Boost. Edit this file, not the generated `<laravel-boost-guidelines>` block, then run `php artisan boost:update`.

## Project

Cendana Studio admin dashboard: Laravel 13 + Blade, originally sliced from the HTML `kenanga-admin-template` starter kit. UI copy, docs and code comments are in **English**. The UI has a **Bahasa Melayu (ms)** translation; never add Bahasa Indonesia text. Served locally via Laravel Herd at `https://cendanastudio.test` (MySQL), so `php artisan serve` is unnecessary.

## Commands

```bash
composer dev                 # server + queue:listen + pail logs + vite, concurrently
npm run dev                  # Vite 8 only (enough under Herd); serves https://vite.cendanastudio.test:5173 via Herd's cert
npm run build                # production asset build
php artisan migrate --seed   # first admin from ADMIN_SEED_* in .env (local fallback test@example.com / password)

php artisan test                                   # all tests (PHPUnit, sqlite :memory:)
php artisan test --filter=test_user_can_log_in_with_valid_credentials
php artisan test tests/Feature/AuthenticationTest.php

vendor/bin/pint --test <changed paths>   # code style; config/auth.php, UserFactory.php and bootstrap/cache already fail, so don't run it repo-wide

npm run docs:dev             # VitePress docs site in docs/
npm run docs:build           # fails on dead page links (not on dead #anchors)
```

Frontend toolchain: Vite 8 + `laravel-vite-plugin` 3 + Tailwind 4 (`@tailwindcss/vite`). The dev server writes `public/hot` while running; the user runs it in their own terminal, so never stop or replace their process; ask them to restart it after frontend dependency upgrades.

Security audits: run `composer audit` and `npm audit` after dependency changes. Three npm advisories are known and accepted: VitePress 1.6.4 bundles its own Vite 5/esbuild (only affects `npm run docs:dev`). Wait for a stable VitePress 2 instead of installing the alpha.

README's validation checklist before finishing: `php artisan test`, `php artisan view:cache` (catches Blade compile errors), `npm run build`. Run `npm run docs:build` too when docs change.

Tests: `AuthenticationTest` (Fortify flows), `ExampleTest` (every page renders, asserting configured brand names), `LocaleTest` (EN default, MS switch, Malay validation), `DatabaseSeederTest`, `AuditLoggingTest` (what gets recorded: sign-in/out, failed sign-in, lockout, profile, password, reset, roles, user create/delete, silent seeding), `UserAgentTest` (browser/system labels), `DataDictionaryTest` (access, category counts, item list, options in both languages, seeder fills every category and keeps edits, add/edit/validation/status toggle, cross-category 404), `AuditTrailTest` (access by role, filters, local-day date range, pagination, menu visibility, detail page changes/hidden secrets/related activity/back link), `RolesAndPermissionsTest` (role-granted permissions, `role:`/`permission:` middleware), `RoleSeederTest` (all roles seeded, admin is Super Admin, Super Admin bypass, one demo user per role outside production), plus one wiring test per package: `ActivityLogTest`, `MediaLibraryTest`, `SpreadsheetExportTest`, `PdfTest`. phpunit.xml doesn't override `ADMIN_*`, so tests read `.env` branding; assert `config('cendana.*')` values, never literal brand text.

Deploying to production (in order): `composer install --no-dev --optimize-autoloader` (keeps Debugbar out), `php artisan migrate --force`, `php artisan storage:link` (media files), `npm run build`, `php artisan optimize`. Seed only once, after setting `ADMIN_SEED_*` and `APP_ENV=production`, `APP_DEBUG=false` in the server's `.env`.

2. The Boost `laravel-best-practices` skill (`.claude/skills/laravel-best-practices`, not the `anthropic-skills` one of the same name) decides code patterns.
3. `superpowers-laravel` skills drive workflow (brainstorm, plan, TDD, review). Apply their pattern advice (Form Requests, Actions/DTOs, ports and adapters) only where it matches the app's current altitude.
4. Run Pint only on changed paths, never repo-wide; don't add PHPStan/Insights or switch tests from PHPUnit to Pest unless asked. No Sail: run commands on the host (Herd).

## Git workflow

Remote `origin` is `git@github.com:nanno619/cendanastudio.git`. Always create commits through the `commit` skill (`.claude/skills/commit`, committed to the repo): read the staged diff, then write a Conventional Commits message (`type(scope): description` + short imperative bullet body) **without** a `Co-Authored-By` trailer. If the skill isn't available, follow that same format by hand. Work on a short-lived branch, then fast-forward merge into `main` and delete the branch. Commit, merge or push only when asked. `.env`, `CLAUDE.md` and `.claude/skills/*` are git-ignored, except the hand-maintained `.claude/skills/commit/`, which is tracked; `CLAUDE.md` and the other skills are generated by Laravel Boost, so change project rules here in `.ai/guidelines/cendana.md` and run `php artisan boost:update` (also run automatically after `composer update`). When a change both renames and rewrites files (e.g. translations), commit the pure rename first so `git log --follow` keeps history.

## Architecture

**Mostly presentational.** `routes/web.php` uses `Route::view` for nearly every page. App controllers: `LocaleController`, plus `Administration\AuditTrailController` and `Administration\AuditTrailEntryController` (invokable; `/administrations/audit-trail` and `/administrations/audit-trail/{activity}`, behind `role:Super Admin`). The list `spatie/laravel-activitylog` entries with server-side filters (`q`, `event`, `user`, `from`/`to`) and 20-per-page pagination via `<x-ui.pagination>`; the detail page shows before/after values from `attribute_changes` (never the values of `password`, `remember_token` or two-factor fields), `properties` as context (`ip`, `user_agent`), and other activity on the same subject (or by the same user). `<x-admin.audit-event>` renders an event badge and `<x-admin.audit-value>` one recorded value. **Data Dictionary** (`/administrations/data-dictionary`, Super Admin only; `DataDictionaryController` lists categories, `DataDictionaryCategoryController` shows one category's items, bound from the URL by the enum): reference values for dropdowns live in the `lookup_items` table (`LookupItem`: `category`, `code`, `label_en`, `label_ms`, `sort_order`, `is_active`, `tone`; unique per category+code). Categories are the `App\Enums\LookupCategory` cases (code-defined, with English `label()`/`description()` translated at render); add a case to add a category. Items are deactivated, never deleted, and their `code` never changes because records store it. Super Admin adds/edits items through `items.create`/`items.store`/`items.edit`/`items.update` (one invokable controller each, sharing `SaveLookupItemRequest`: code only on create, lowercase-hyphen slug unique per category; English label unique per category; `tone` from `LookupItem::TONES`) and switches them with `items.status` (PATCH, toggles `is_active`; audit description "Activated/Deactivated …"). Controllers `abort_unless($item->category === $category, 404)` since enum route parents can't scope bindings. Success messages are flashed as `status` and shown with `<x-ui.alert>`, not the JS toast (its innerHTML would render item labels as HTML). Use `LookupItem::options(LookupCategory::X)` for dropdowns (active items, ordered, `code => label` in the current language, Malay falling back to English) and the `inCategory()`, `active()`, `ordered()` scopes. Starter values for every category (Malaysian States, Race, Marital Status, Leave Type, Claim Type, Gender, Statuses = leave/claim approval statuses with badge tones) come from `LookupSeeder`, which runs in all environments, never overwrites existing items and writes no audit entries; item edits are audited via `LogsActivity`. `App\Support\UserAgent::describe()` turns a stored `user_agent` into a translated label like "Chrome 142 on macOS" (null when unrecognised, so show the raw string); it is display-only, so add new browsers/systems to its ordered pattern lists and to `UserAgentTest`. Locally `AuditTrailDemoSeeder` fills it with sample entries tagged `log_name = 'demo'` (replaced on each seed, skipped in production). Demo data (records, users, orders, products, activity) comes from `config('cendana.demo.*')`, not the database. Demo forms carry `data-demo-form` and only show a toast. `docs/integration/` describes the intended path to real backend wiring (controllers, models, validation, pagination).

**Auth is real** via Laravel Fortify: `FortifyServiceProvider` registers views (`auth.login`, `auth.forgot-password`, `auth.reset-password`) and the `App\Actions\Fortify\*` actions; login is rate-limited at 5/min per email+IP. All admin pages sit behind `auth` middleware; `/locale`, `/demo/404` and `/testing` are public. The seeder (`DatabaseSeeder`) creates the first admin from `config('cendana.seed_admin')` (`ADMIN_SEED_NAME/EMAIL/PASSWORD`) via `updateOrCreate`; in production it throws without credentials or with a password under 12 chars, locally it falls back to `test@example.com` / `password`.

**Authorization** uses `spatie/laravel-permission` (v8): `User` has the `HasRoles` trait, permissions register on Laravel's gate (`$user->can('edit records')`, `@can`), and the `role`, `permission` and `role_or_permission` middleware aliases are registered in `bootstrap/app.php`. Roles are the `App\Enums\Role` cases (Super Admin, Director, Project Manager, Consultant, Finance, Admin, Staff, Support, Trainee, Sales), created by `RoleSeeder` (called from `DatabaseSeeder`, idempotent); the seeded `ADMIN_SEED_*` admin gets Super Admin. Outside production `RoleUserSeeder` also creates one demo sign-in per other role (`{role-slug}@demo.test` / `password`, e.g. `project-manager@demo.test`); it skips the seeded admin's email and does nothing in production. Super Admin bypasses every check via `Gate::before` in `AppServiceProvider`. No permissions are defined yet and routes aren't role-gated; reference roles through the enum (`$user->hasRole(Role::Finance)`, `'role:'.Role::Finance->value`), never as string literals. Clear `PermissionRegistrar::forgetCachedPermissions()` in tests that create them.

**Packages installed but not yet used by app models** (wire them in when a feature needs them; check the installed major version with `search-docs` before writing code):
- `spatie/laravel-activitylog` v5: audit trail via `activity()->causedBy($user)->performedOn($model)->log('...')` or the `LogsActivity` trait on a model. Table `activity_log`. What is recorded today: `App\Listeners\RecordAuthenticationActivity` (auto-discovered) logs `login`, `logout`, `failed-login` (no causer; subject = account when the email exists; attempted email in properties) and `lockout` (fired from the `login` rate limiter's response in `FortifyServiceProvider`), each with `ip` and `user_agent`; `User` uses `LogsActivity` for `created`/`updated`/`deleted` of name, email, email_verified_at and password, with password values replaced by `[hidden]` (override of `buildChanges`) and "Changed password" as the description when only the password changed; `ResetUserPassword` logs `password-reset` against the user; `App\Listeners\RecordRoleActivity` logs `role-assigned`/`role-removed` from spatie permission events (`permission.events_enabled` is true; `syncRoles` records a removal then an assignment). `DatabaseSeeder` runs inside `activity()->withoutLogging()` so seeding writes nothing. Never log secrets: no passwords, hashes or tokens in properties or changes. New event names need a tone in `<x-admin.audit-event>` and a Malay label for `Str::headline($event)`. In tests, fixtures (factories, `assignRole`) are themselves audited, so clear `Activity` after setup or query by event.
- `spatie/laravel-medialibrary` v11: attach files with `HasMedia` + `InteractsWithMedia` on a model; stored on the `public` disk (`MEDIA_DISK`). GD and Imagick are available for conversions.
- `maatwebsite/excel` v4 (PhpSpreadsheet): put export/import classes in `app/Exports` / `app/Imports`; use `Excel::download()` for CSV/XLSX.
- `barryvdh/laravel-dompdf` v3: `Pdf::loadView('pdf.quote', $data)->download()`; keep PDF Blade views under `resources/views/pdf/` with inline CSS (no Vite/Tailwind in PDFs).
- `barryvdh/laravel-debugbar` v4 (dev only): on when `APP_DEBUG=true`, forced off in tests via `DEBUGBAR_ENABLED=false` in `phpunit.xml`. Deploy with `composer install --no-dev` so it never reaches production.

**`config/cendana.php` drives the shell**: branding (from `ADMIN_*` env vars: `ADMIN_NAME` = browser title suffix, `ADMIN_BRAND_NAME`, `ADMIN_WORKSPACE` + `_DESCRIPTION` = sidebar/login, `ADMIN_FOOTER` = footer text), `seed_admin`, `locales`, sidebar `navigation` (groups → items with `route`, `active` route pattern, `icon`, optional `children`), theme accent list and radius options. Adding a page = route + view + navigation entry. `ADMIN_TIMEZONE` (default `Asia/Kuala_Lumpur`) is `cendana.timezone`, the zone pages display times in; `app.timezone` stays UTC for storage, so convert with `->timezone(config('cendana.timezone'))` and turn local date filters into UTC bounds. A navigation item with a `'role' => Role::X->value` key is shown only to users with that role, and a group with no visible items is hidden; an item without a `route` renders as a disabled placeholder. `ADMIN_SHOWCASE=false` removes the `/components/*` and `/examples/records/*` routes entirely (they are registered inside `if (config('cendana.showcase'))`).

**Blade components** (`resources/views/components/`):
- `layouts/` — `<x-layouts.admin title="" group="">` (sidebar + header + customizer + `#toasts`), `guest`, `blank`.
- `admin/` — app shell pieces (sidebar, header, nav-link, customizer).
- `ui/` — reusable `<x-ui.*>` library (card, button, field, modal, drawer, combobox, date-range, table-state, chart, etc.). Documented per component in `docs/components/`; the live catalog is `resources/views/showcase/`. Reuse these rather than writing raw markup.
- Icons: use `<x-ui.icon name="">` (external sprite `public/icons.svg#i-{name}`). The legacy `<x-icon>` references an inline `#i-{name}` symbol the layouts don't load; don't use it. No CDN for icons or fonts (Inter via `@fontsource`).

**Frontend JS** (`resources/js/admin/`, imported by `resources/js/app.js`) is vanilla, global, and driven by **event delegation on `data-*` attributes** — `data-dropdown`, `data-tabs`, `data-collapse`, `data-modal-open`/`data-modal-close` (native `<dialog>`), `data-table` (client-side search/filter/paginate), `data-toast`, `data-dismiss`, `data-copy`, `data-pref`. New interactive behavior should follow the same attribute pattern rather than per-page scripts. `charts.js` renders SVG charts from props passed by `<x-ui.chart>`; `advanced-inputs.js` handles combobox/date-range/file preview (choices.js, flatpickr).

**Theming**: Tailwind CSS 4 via `@tailwindcss/vite` (no `tailwind.config.js`); design tokens, light/dark themes, accent and radius variables and component classes live in `resources/css/app.css`. User preferences (theme, accent, radius, sidebar mini/full) are stored in `localStorage` only — no backend.

**Localization (en default, ms translation)**: `config('cendana.locales')` lists languages; `App\Http\Middleware\SetLocale` (appended to the web group) applies `session('locale')`, set by `POST /locale` (`LocaleController`, route `locale.update`) from `<x-locale.switcher>`. Rules:
- Blade text: write English inside `__()` and add the Malay value to `lang/ms.json` (keyed by the English string). Don't use a key that matches a translation group file name (e.g. `Pagination`) — macOS's case-insensitive FS resolves it to `lang/*/pagination.php` and returns an array.
- Config strings (`navigation` labels, accent/radius names, demo statuses) stay English in `config/cendana.php` and are wrapped in `__()` where rendered, since config loads before the locale is known. Filter/status *keys* (`active`, `draft`, `in-review`…) are untranslated slugs matched by JS `data-status` filters.
- JS strings live in `lang/{en,ms}/js.php`, exposed as `window.__i18n` by `layouts/head.blade.php`; scripts call `__t('key', {placeholder: value})`.
- Inside `@props` defaults use `null` and fill with `@php $x ??= __('...'); @endphp` (block form — inline `@php(...)` breaks when the file also has an `@php` block). Blade's `@json()` splits on commas, so use `{{ json_encode([...]) }}` for array literals in `data-*` attributes.
- In VitePress docs, `{{ }}` inside inline code is evaluated by Vue; wrap such spans in `<span v-pre>`.

**Currency & numbers are Malaysian**: money is MYR (`RM 48.00`, `RM 16.7k`), numbers use dot decimals and comma thousands (`1,284`, `+13.2%`). JS formats with `toLocaleString('ms-MY')`. Demo amounts in views/config were hand-converted from Rupiah (~Rp 3,500 = RM 1) and the sample coffee-shop data (names, products, cities) is intentionally kept.

**Docs** (`docs/`, VitePress, English): `guide/` (getting-started, structure, pages, theming incl. `#language`), `components/` (one page per `<x-ui.*>` plus overviews: layout, forms, tables, charts, feedback, interactions, data-patterns), `integration/` (crud, forms, data, auth). Sidebar/nav live in `docs/.vitepress/config.mts`; update them when adding or renaming a page. Keep docs consistent with the code (e.g. examples use `__()` and English slugs).

`resources/views/welcome.blade.php` is Laravel's unused default page; `/` redirects to `/dashboard`.

**`tools/convert-template-to-blade.mjs`** converts a source template HTML page (with `<!--page ...-->` metadata and `{{> partial attr=""}}` includes) into a Blade view; used for porting additional pages from the original template.
