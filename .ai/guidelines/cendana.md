# Cendana Studio project guidelines

These project-specific rules are composed into CLAUDE.md by Laravel Boost. Edit this file, not the generated `<laravel-boost-guidelines>` block, then run `php artisan boost:update`.

## Project

Cendana Studio admin dashboard: Laravel 13 + Blade, originally sliced from the HTML `kenanga-admin-template` starter kit. UI copy, docs and code comments are in **English**. The UI has a **Bahasa Melayu (ms)** translation; never add Bahasa Indonesia text. Served locally via Laravel Herd at `https://cendanastudio.test` (MySQL), so `php artisan serve` is unnecessary.

## Commands

```bash
composer dev                 # server + queue:listen + pail logs + vite, concurrently
npm run dev                  # vite only (enough under Herd)
npm run build                # production asset build
php artisan migrate --seed   # first admin from ADMIN_SEED_* in .env (local fallback test@example.com / password)

php artisan test                                   # all tests (PHPUnit, sqlite :memory:)
php artisan test --filter=test_user_can_log_in_with_valid_credentials
php artisan test tests/Feature/AuthenticationTest.php

vendor/bin/pint --test <changed paths>   # code style; config/auth.php, UserFactory.php and bootstrap/cache already fail, so don't run it repo-wide

npm run docs:dev             # VitePress docs site in docs/
npm run docs:build           # fails on dead page links (not on dead #anchors)
```

README's validation checklist before finishing: `php artisan test`, `php artisan view:cache` (catches Blade compile errors), `npm run build`. Run `npm run docs:build` too when docs change.

Tests: `AuthenticationTest` (Fortify flows), `ExampleTest` (every page renders, asserting configured brand names), `LocaleTest` (EN default, MS switch, Malay validation), `DatabaseSeederTest`. phpunit.xml doesn't override `ADMIN_*`, so tests read `.env` branding; assert `config('cendana.*')` values, never literal brand text.

## Git workflow

Remote `origin` is `git@github.com:nanno619/cendanastudio.git`. Commit messages follow Conventional Commits (`type(scope): description` + short bullet body) per the user's `commit` skill, **without** a `Co-Authored-By` trailer. Work on a short-lived branch, then fast-forward merge into `main` and delete the branch. Commit, merge or push only when asked. `.env`, `CLAUDE.md` and `.claude/skills/` are git-ignored; the last two are generated by Laravel Boost, so change project rules here in `.ai/guidelines/cendana.md` and run `php artisan boost:update` (also run automatically after `composer update`). When a change both renames and rewrites files (e.g. translations), commit the pure rename first so `git log --follow` keeps history.

## Architecture

**Mostly presentational.** `routes/web.php` uses `Route::view` for nearly every page; the only app controller is `LocaleController`. Demo data (records, users, orders, products, activity) comes from `config('cendana.demo.*')`, not the database. Demo forms carry `data-demo-form` and only show a toast. `docs/integration/` describes the intended path to real backend wiring (controllers, models, validation, pagination).

**Auth is real** via Laravel Fortify: `FortifyServiceProvider` registers views (`auth.login`, `auth.forgot-password`, `auth.reset-password`) and the `App\Actions\Fortify\*` actions; login is rate-limited at 5/min per email+IP. All admin pages sit behind `auth` middleware; `/locale`, `/demo/404` and `/testing` are public. The seeder (`DatabaseSeeder`) creates the first admin from `config('cendana.seed_admin')` (`ADMIN_SEED_NAME/EMAIL/PASSWORD`) via `updateOrCreate`; in production it throws without credentials or with a password under 12 chars, locally it falls back to `test@example.com` / `password`.

**`config/cendana.php` drives the shell**: branding (from `ADMIN_*` env vars: `ADMIN_NAME` = browser title suffix, `ADMIN_BRAND_NAME`, `ADMIN_WORKSPACE` + `_DESCRIPTION` = sidebar/login, `ADMIN_FOOTER` = footer text), `seed_admin`, `locales`, sidebar `navigation` (groups → items with `route`, `active` route pattern, `icon`, optional `children`), theme accent list and radius options. Adding a page = route + view + navigation entry. `ADMIN_SHOWCASE=false` removes the `/components/*` and `/examples/records/*` routes entirely (they are registered inside `if (config('cendana.showcase'))`).

**Blade components** (`resources/views/components/`):
- `layouts/` — `<x-layouts.admin title="" group="">` (sidebar + header + customizer + `#toasts`), `guest`, `blank`.
- `admin/` — app shell pieces (sidebar, header, nav-link, customizer).
- `ui/` — reusable `<x-ui.*>` library (card, button, field, modal, drawer, combobox, date-range, table-state, chart, etc.). Documented per component in `docs/components/`; the live catalog is `resources/views/showcase/`. Reuse these rather than writing raw markup.
- Two icon components: `<x-ui.icon name="">` references the external sprite `public/icons.svg#i-{name}`; `<x-icon>` references an inline `#i-{name}` symbol. No CDN for icons or fonts (Inter via `@fontsource`).

**Frontend JS** (`resources/js/admin/`, imported by `resources/js/app.js`) is vanilla, global, and driven by **event delegation on `data-*` attributes** — `data-dropdown`, `data-tabs`, `data-collapse`, `data-modal-open`/`data-modal-close` (native `<dialog>`), `data-table` (client-side search/filter/paginate), `data-toast`, `data-dismiss`, `data-copy`, `data-pref`. New interactive behavior should follow the same attribute pattern rather than per-page scripts. `charts.js` renders SVG charts from props passed by `<x-ui.chart>`; `advanced-inputs.js` handles combobox/date-range/file preview (choices.js, flatpickr).

**Theming**: Tailwind CSS 4 via `@tailwindcss/vite` (no `tailwind.config.js`); design tokens, light/dark themes, accent and radius variables and component classes live in `resources/css/app.css`. User preferences (theme, accent, radius, sidebar mini/full) are stored in `localStorage` only — no backend.

**Localization (en default, ms translation)**: `config('cendana.locales')` lists languages; `App\Http\Middleware\SetLocale` (appended to the web group) applies `session('locale')`, set by `POST /locale` (`LocaleController`, route `locale.update`) from `<x-locale.switcher>`. Rules:
- Blade text: write English inside `__()` and add the Malay value to `lang/ms.json` (keyed by the English string). Don't use a key that matches a translation group file name (e.g. `Pagination`) — macOS's case-insensitive FS resolves it to `lang/*/pagination.php` and returns an array.
- Config strings (`navigation` labels, accent/radius names, demo statuses) stay English in `config/cendana.php` and are wrapped in `__()` where rendered, since config loads before the locale is known. Filter/status *keys* (`active`, `draft`, `in-review`…) are untranslated slugs matched by JS `data-status` filters.
- JS strings live in `lang/{en,ms}/js.php`, exposed as `window.__i18n` by `layouts/head.blade.php`; scripts call `__t('key', {placeholder: value})`.
- Inside `@props` defaults use `null` and fill with `@php $x ??= __('...'); @endphp` (block form — inline `@php(...)` breaks when the file also has an `@php` block). Blade's `@json()` splits on commas, so use `{{ json_encode([...]) }}` for array literals in `data-*` attributes.
- In VitePress docs, `{{ }}` inside inline code is evaluated by Vue; wrap such spans in `<span v-pre>`.

**Currency & numbers are Malaysian**: money is MYR (`RM 48.00`, `RM 16.7k`), numbers use dot decimals and comma thousands (`1,284`, `+13.2%`). JS formats with `toLocaleString('ms-MY')`. Demo amounts in views/config were hand-converted from Rupiah (~Rp 3,500 = RM 1) and the sample coffee-shop data (names, products, cities) is intentionally kept.

**Docs** (`docs/`, VitePress, English): `guide/` (getting-started, structure, pages, theming incl. `#language`), `components/` (one page per `<x-ui.*>` plus overviews: layout, forms, tables, charts, feedback, interactions, data-patterns), `integration/` (crud, forms, data, auth). Sidebar/nav live in `docs/.vitepress/config.mts`; update them when adding or renaming a page. Keep docs consistent with the code (e.g. examples use `__()` and English slugs).

`resources/views/welcome.blade.php` is Laravel's unused default page; `/` redirects to `/dashboard`.

**`tools/convert-template-to-blade.mjs`** converts a source template HTML page (with `<!--page ...-->` metadata and `{{> partial attr=""}}` includes) into a Blade view; used for porting additional pages from the original template.
