# Cendana Studio project guidelines

These project-specific rules are composed into CLAUDE.md by Laravel Boost. Edit this file, not the generated `<laravel-boost-guidelines>` block, then run `php artisan boost:update`.

## Project

Cendana Studio admin dashboard: Laravel 13 + Blade, originally sliced from the HTML `kenanga-admin-template` starter kit. UI copy, docs and code comments are in **English**. The UI has a **Bahasa Melayu (ms)** translation; never add Bahasa Indonesia text. Served locally via Laravel Herd at `https://cendanastudio.test` (MySQL), so `php artisan serve` is unnecessary.

## Commands

```bash
composer dev                 # server + queue:listen + pail logs + vite, concurrently
npm run dev                  # Vite 8 only (enough under Herd); serves https://vite.cendanastudio.test:5173 via Herd's cert
npm run build                # production asset build
php artisan migrate --seed   # first admin from ADMIN_SEED_* in .env (local fallback test@example.com / password)

php artisan test                                   # all tests (PHPUnit, sqlite :memory:)
php artisan test --filter=test_user_can_log_in_with_valid_credentials
php artisan test tests/Feature/AuthenticationTest.php

vendor/bin/pint --test <changed paths>   # code style; config/auth.php, UserFactory.php and bootstrap/cache already fail, so don't run it repo-wide

npm run docs:dev             # VitePress docs site in docs/
npm run docs:build           # fails on dead page links (not on dead #anchors)
```

Frontend toolchain: Vite 8 + `laravel-vite-plugin` 3 + Tailwind 4 (`@tailwindcss/vite`). The dev server writes `public/hot` while running; the user runs it in their own terminal, so never stop or replace their process; ask them to restart it after frontend dependency upgrades.

Security audits: run `composer audit` and `npm audit` after dependency changes. Three npm advisories are known and accepted: VitePress 1.6.4 bundles its own Vite 5/esbuild (only affects `npm run docs:dev`). Wait for a stable VitePress 2 instead of installing the alpha.

## Skills

Always activate the `laravel-best-practices` skill before writing, reviewing or refactoring Laravel PHP (controllers, models, migrations, routes, validation, policies, jobs, Eloquent queries). This project's own rules take precedence where they differ.

Precedence when skills disagree:
1. Project rules (this file and `.ai/rules`) win over any skill, including instructions to follow a skill "exactly as written".
2. The Boost `laravel-best-practices` skill (`.claude/skills/laravel-best-practices`, not the `anthropic-skills` one of the same name) decides code patterns.
3. `superpowers-laravel` skills drive workflow (brainstorm, plan, TDD, review). Apply their pattern advice (Form Requests, Actions/DTOs, ports and adapters) only where it matches the app's current altitude.
4. Run Pint only on changed paths, never repo-wide; don't add PHPStan/Insights or switch tests from PHPUnit to Pest unless asked. No Sail: run commands on the host (Herd).

## Git workflow

Remote `origin` is `git@github.com:nanno619/cendanastudio.git`. Always create commits through the `commit` skill (`.claude/skills/commit`, committed to the repo): read the staged diff, then write a Conventional Commits message (`type(scope): description` + short imperative bullet body) **without** a `Co-Authored-By` trailer. If the skill isn't available, follow that same format by hand. Work on a short-lived branch, then fast-forward merge into `main` and delete the branch. Commit, merge or push only when asked. `.env`, `CLAUDE.md` and `.claude/skills/*` are git-ignored, except the hand-maintained `.claude/skills/commit/`, which is tracked; `CLAUDE.md` and the other skills are generated by Laravel Boost, so change project rules here in `.ai/guidelines/cendana.md` and run `php artisan boost:update` (also run automatically after `composer update`). When a change both renames and rewrites files (e.g. translations), commit the pure rename first so `git log --follow` keeps history.

## Architecture

**Mostly presentational.** `routes/web.php` uses `Route::view` for nearly every page. App controllers: `LocaleController`, plus `Administration\AuditTrailController` and `Administration\AuditTrailEntryController` (invokable; `/administrations/audit-trail` and `/administrations/audit-trail/{activity}`, behind `role:Super Admin`). The list `spatie/laravel-activitylog` entries with server-side filters (`q`, `event`, `user`, `from`/`to`) and 20-per-page pagination via `<x-ui.pagination>`; the detail page shows before/after values from `attribute_changes` (never the values of `password`, `remember_token` or two-factor fields), `properties` as context (`ip`, `user_agent`), and other activity on the same subject (or by the same user). `<x-admin.audit-event>` renders an event badge and `<x-admin.audit-value>` one recorded value. **Data Dictionary** (`/administrations/data-dictionary`, Super Admin only; `DataDictionaryController` lists categories, `DataDictionaryCategoryController` shows one category's items, bound from the URL by the enum): reference values for dropdowns live in the `lookup_items` table (`LookupItem`: `category`, `code`, `label_en`, `label_ms`, `sort_order`, `is_active`, `tone`; unique per category+code). Categories are the `App\Enums\LookupCategory` cases (code-defined, with English `label()`/`description()` translated at render); add a case to add a category. Items are deactivated, never deleted, and their `code` never changes because records store it. Super Admin adds/edits items through `items.create`/`items.store`/`items.edit`/`items.update` (one invokable controller each, sharing `SaveLookupItemRequest`: code only on create, lowercase-hyphen slug unique per category; English label unique per category; `tone` from `LookupItem::TONES`) and switches them with `items.status` (PATCH, toggles `is_active`; audit description "Activated/Deactivated …"). Controllers `abort_unless($item->category === $category, 404)` since enum route parents can't scope bindings. Success messages are flashed as `status` and shown with `<x-ui.alert>`, not the JS toast (its innerHTML would render item labels as HTML). Use `LookupItem::options(LookupCategory::X)` for dropdowns (active items, ordered, `code => label` in the current language, Malay falling back to English) and the `inCategory()`, `active()`, `ordered()` scopes. Starter values for every category (Malaysian States, Race, Marital Status, Leave Type, Claim Type, Gender, Statuses = leave/claim approval statuses with badge tones, Banks = Malaysian banks; Leave Type includes maternity, marriage, replacement and unpaid) come from `LookupSeeder`, which runs in all environments, never overwrites existing items and writes no audit entries; item edits are audited via `LogsActivity`. **File Security** (`/administrations/file-security`, Super Admin only; `FileSecurityController` shows and `UpdateFileSecurityController` + `UpdateFileSecurityRequest` saves) holds the upload policy in the single-row `file_security_settings` table (`FileSecuritySetting`: `allowed_types` = `AsEnumCollection` of `App\Enums\FileType` groups with `extensions()`/`mimeTypes()`, `max_file_size_mb` capped at PHP's `upload_max_filesize`/`post_max_size`, `verify_content`). `FileSecuritySetting::current()` returns the row, or the defaults before one exists; `FileSecuritySettingSeeder` (all environments, never overwrites, no audit) creates it, and saves are audited via `LogsActivity` ("Updated file security settings"). Validate every upload with `new App\Rules\AllowedUpload` (allowed type by final extension, size, Media Library's `disallowed_extensions` in any name segment, detected MIME when `verify_content` is on) instead of hard-coded `mimes`/`max` rules. Add a file type by adding a `FileType` case. **Log Viewer** (`/administrations/log-viewer`, a `Route::view`) embeds `opcodesio/log-viewer` (v3, UI at `/log-viewer`, assets served from vendor, no publish step) in an iframe so the app shell stays. `config/log-viewer.php` adds `auth` to its page and API middleware and shows times in `ADMIN_TIMEZONE`; the `viewLogViewer` gate in `AppServiceProvider` denies everyone, so only Super Admin (via `Gate::before`) gets in, in every environment. Super Admin can also download and delete log files there. `App\Support\UserAgent::describe()` turns a stored `user_agent` into a translated label like "Chrome 142 on macOS" (null when unrecognised, so show the raw string); it is display-only, so add new browsers/systems to its ordered pattern lists and to `UserAgentTest`. Locally `AuditTrailDemoSeeder` fills it with sample entries tagged `log_name = 'demo'` (replaced on each seed, skipped in production). Demo data (records, users, orders, products, activity) comes from `config('cendana.demo.*')`, not the database. Demo forms carry `data-demo-form` and only show a toast. `docs/integration/` describes the intended path to real backend wiring (controllers, models, validation, pagination).

**Table keys**: every new table keeps an auto-increment `id` primary key plus a `$table->ulid()->unique()` column. Its model uses `HasUlids` with `uniqueIds()` returning `['ulid']` (so `id` stays an incrementing integer) and `getRouteKeyName()` returning `'ulid'`, so URLs never expose `id`. Tables created before this rule (`users`, `lookup_items`, `file_security_settings`, …) are not retrofitted unless asked.

**Company** (Settings → Company → Basic Details, `/settings/company/basic-details`, Super Admin only; `Settings\CompanyDetailsController` shows and `Settings\UpdateCompanyDetailsController` + `UpdateCompanyDetailsRequest` saves, creating the row on first save): the single-row `companies` table (`Company`: name, SSM `registration_no` + `old_registration_no`, contact, address with `state` = a `LookupCategory::MalaysianStates` code and `country` ISO code defaulting to `MY`, plus the `Company::BANK_ACCOUNT_FIELDS` columns below). Only `name` is required in the schema. `Company::current()` returns the row, or an unsaved company before the details are first saved; there's no seeder. The logo is the single-file `logo` media collection, uploaded through `<x-ui.file-preview name="logo">` and validated with `['image', new AllowedUpload]` (a `remove_logo` switch clears it); logo changes aren't audited. The request strips spaces/dashes from `registration_no` (12 digits) and uppercases `old_registration_no` (`1234567-A`); `state` must be an active Malaysian-states code, `postcode` 5 digits. Field changes are audited via `LogsActivity` ("Created/Updated company details", or "Updated company bank account details" when only `BANK_ACCOUNT_FIELDS` changed; account numbers are logged in full, they aren't secrets). **Bank Account Details** (`/settings/company/bank-account-details`, `Settings\CompanyBankAccountDetailsController` shows, `Settings\UpdateCompanyBankAccountDetailsController` + `UpdateCompanyBankAccountDetailsRequest` saves) edits `BANK_ACCOUNT_FIELDS`: `bank` (an active `LookupCategory::Banks` code), `bank_account_holder`, `bank_account_no` (spaces/dashes stripped, 5–20 digits) and the statutory numbers `epf_no` (Malaysian staff), `epf_foreign_no` (non-Malaysian), `socso_no`, `eis_no`, `income_tax_no` (LHDN E-number), `zakat_no`, `hrdf_no`, `ptptn_no`; Basic Details no longer edits them. It needs the company row, so before Basic Details is first saved the form is disabled and saving returns a `company` error. Settings pages live under the `settings.` route name prefix behind `role:Super Admin`; the existing `/settings` (`admin.settings`) is the user's account settings, unrelated.

**Leave settings** (Settings → Leave → General, `/settings/leave/general`, Super Admin only; `Settings\LeaveSettingsController` shows and `Settings\UpdateLeaveSettingsController` + `UpdateLeaveSettingsRequest` saves, creating the row on first save): the single-row `leave_settings` table (`LeaveSetting`, id + ULID). `LeaveSetting::current()` returns the row, or an unsaved one filled from `LeaveSetting::defaults()`; there's no seeder. Columns: `leave_year_start_month`, `working_days` (`AsEnumCollection` of `App\Enums\Weekday`, ISO 1 = Monday like Carbon's `isoWeekday()`, stored Monday first), `half_working_day` (a `Weekday` that must be a working day), `public_holiday_state` (a Malaysian-states code; the form preselects the company's state before the first save), `allow_half_day`, `annual_leave_notice_days` and `backdate_days` (0–90, 0 = none/not allowed), `allow_leave_during_probation` (annual leave only), `allow_negative_balance` + `max_negative_days` (0.5–30 in half days, null while borrowing is off), `prorate_entitlement` + `proration_rounding` (`App\Enums\LeaveRounding`, default `nearest-day` per the Employment Act), `resignation_unused_leave` (`App\Enums\UnusedLeaveTreatment`), `share_leave_calendar` and `hr_notification_email`. Saves are audited as "Updated leave settings". The Leave module will read these rules when it's built. With the shared calendar on, staff see only who is on leave, never the leave type; Super Admin and Admin count as HR and always see full details. "Include former staff" is a filter on the future leave report, not a setting.

**Leave Policies** (Settings → Leave → Leave Policies, `/settings/leave/policies`, Super Admin only; `Settings\LeavePolicyController` lists, `Settings\EditLeavePolicyController` shows and `Settings\UpdateLeavePolicyController` + `UpdateLeavePolicyRequest` saves): one `leave_policies` row per Data Dictionary leave type (`LeavePolicy`, id + ULID, `leave_type` = a `LookupCategory::LeaveType` code, unique). Routes take the leave type code (`/settings/leave/policies/annual/edit`); controllers resolve the active Leave Type item or 404, and a type without a row shows "Not set up" until its first save (`LeavePolicy::for($code)` returns an unsaved one). Columns: `is_paid`, `requires_attachment`, `entitlements` (JSON tiers `[{min_years, days}]` sorted by years, first tier from 0, days in half days; empty = no fixed entitlement), `allow_carry_forward` + `carry_forward_max_days` + `carry_forward_expiry_months` (months into the new leave year, null = never; both null while carry forward is off). `entitlementFor($yearsOfService)` returns the days of the highest tier reached, or null. The edit form has 5 fixed tier rows, no JS; blank rows are dropped in `prepareForValidation`. Saves are audited ("Created/Updated leave policy"). `LeavePolicySeeder` (all environments, after `LookupSeeder` in `DatabaseSeeder`, never overwrites, skips types missing from the Data Dictionary, no audit) seeds Employment Act 1955 minimums: annual 8/12/16 and sick 14/18/22 days (from 0/2/5 years), hospitalisation 60, maternity 98, paternity 7, compassionate 3, marriage 3, replacement and unpaid with no fixed entitlement. Eligibility (minimum service, gender) and per-application limits were left out on purpose.

**Leave Approval** (Settings → Leave → Leave Approval, `/settings/leave/approval`, Super Admin only; `Settings\LeaveApprovalController` lists, `Create/Store/Edit/Update/DestroyLeaveApprovalRouteController` + shared `SaveLeaveApprovalRouteRequest` manage routes, `UpdateLeaveCancellationController` saves the cancellation rule): `leave_approval_routes` (`LeaveApprovalRoute`, id + ULID, bound by ULID as `{approvalRoute}`) holds one route per applicant role (`applicant_role` = `App\Enums\Role`, unique) plus one default route with a null role ("Everyone else"; one only, enforced in the request's `after()` and the seeder; it can't be deleted, 403). `levels` is a JSON list run in order, 1 to `LeaveApprovalRoute::MAX_LEVELS` (5): `{type: role, value: Role value}` (anyone with the role approves) or `{type: user, value: user id}` (users have no ULID). The form has 5 rows, each one `<select>` with Roles/Users optgroups posting `role:<Role>` or `user:<id>` (no JS); blank rows are dropped and `SaveLeaveApprovalRouteRequest::parseLevel()` checks the role or user exists. A route's role is fixed after creation. Deleted users are flagged "User no longer exists". `LeaveApprovalRoute::forRole($role)` returns the role's route, else the default, else null; when no approver is usable, Super Admin decides. `LeaveApprovalRouteSeeder` (all environments, after `LeavePolicySeeder`, never overwrites, no audit) creates the default route approved by role Admin. `cancellation_requires_approval` (on `leave_settings`, default true) is saved from this page's switch via `LeaveSetting::current()`. Audited: "Created/Updated/Deleted leave approval route", the switch as "Updated leave settings". Left for later: no-self-approval, escalation, auto-approve, reporting-manager approvers (needs staff records).

**Payroll settings** (Settings → Payroll → General, `/settings/payroll/general`, Super Admin only; `Settings\PayrollSettingsController` shows and `Settings\UpdatePayrollSettingsController` + `UpdatePayrollSettingsRequest` saves, creating the row on first save): the single-row `payroll_settings` table (`PayrollSetting`, id + ULID, `current()` = the row or an unsaved one from `defaults()`, no seeder; same pattern as `LeaveSetting`). Columns: `pay_day_rule` (`App\Enums\PayDayRule`: fixed day of the month, last working day, or a day of the following month) + `pay_day` (1–31 same month; 1–`PayrollSetting::LATEST_PAY_DAY_NEXT_MONTH` (7) next month, the Employment Act deadline; null for the last working day), `pay_day_adjustment` (`PayDayAdjustment`, uses Leave → General's working days and holiday state), `cutoff_day`, `socso_enabled`, `eis_enabled`, `pcb_enabled` + `pcb_method` (`PcbMethod`), `hrdf_levy` (`HrdfLevy`: none, 0.5%, 1%), `zakat_via_payroll`, `payment_method` (`PaymentMethod`, bank transfers from Bank Account Details), `net_pay_rounding` (`NetPayRounding`: sen, 5 sen, ringgit), `requires_approval` + `approver_role` (`Role`, null while approval is off), `lock_after_release`. Saves are audited as "Updated payroll settings". EPF, overtime, pro-rata and payslips belong on their own Payroll pages. The Payroll module will read these rules when it's built.

**EPF settings** (Settings → Payroll → EPF, `/settings/payroll/epf`, Super Admin only; `Settings\EpfSettingsController` shows and `Settings\UpdateEpfSettingsController` + `UpdateEpfSettingsRequest` saves): the single-row `epf_settings` table (`EpfSetting`, id + ULID, `current()` = the row or an unsaved one from `defaults()`, no seeder). Rates (`EpfSetting::RATE_FIELDS`, percentages 0–30 with up to 2 decimals) default to the statutory KWSP rates as of October 2025: Malaysian under 60 employee 11%, employer 13% up to `wage_threshold` (RM5,000) and 12% above; Malaysian 60 and over employee 0%, employer 4%; non-Malaysian 2% and 2%. `calculation_method` (`App\Enums\EpfCalculationMethod`: Third Schedule table or exact percentage; both round up to the next ringgit). `allow_employer_top_up` + `employer_top_up_rate` (must be above the statutory employer rate; null while off) and `allow_employee_elected_rate` (each person's rate belongs on their future staff record). Fixed rules are shown, not stored: 60-and-over rates start the month after the 60th birthday, contributions are due by the 15th of the following month (`EpfSetting::PAYMENT_DUE_DAY`), and employer EPF numbers live on Company → Bank Account Details. Which pay items are EPF-liable belongs with pay items when payroll is built. Saves are audited as "Updated EPF settings".

**Overtime settings** (Settings → Payroll → Overtime, `/settings/payroll/overtime`, Super Admin only; `Settings\OvertimeSettingsController` shows and `Settings\UpdateOvertimeSettingsController` + `UpdateOvertimeSettingsRequest` saves): the single-row `overtime_settings` table (`OvertimeSetting`, id + ULID, `current()` = the row or an unsaved one from `defaults()`, no seeder). Overtime **pay** only; how overtime time is recorded, rounded and approved belongs to Hadir → Overtime. `eligibility` (`App\Enums\OvertimeEligibility`: Employment Act staff up to `eligibility_wage_limit`, default RM4,000, null for all staff), multipliers of the hourly rate `normal_day_rate`, `rest_day_rate`, `public_holiday_rate` (hours beyond normal hours) that can't go below the Employment Act minimums `OvertimeSetting::MIN_*_RATE` (1.5×, 2×, 3×), `normal_hours_per_day` (1–10 in half hours) and `monthly_limit_hours` (up to `MAX_MONTHLY_HOURS`, 104). `hourlyRate($monthlyWage)` = wages ÷ `ORDINARY_RATE_DIVISOR` (26) ÷ normal hours. Fixed rules are shown, not stored: rest-day and public-holiday pay within normal hours, overtime not EPF-liable, the cut-off day from Payroll → General. Saves are audited as "Updated overtime settings".

**Pro-rata settings** (Settings → Payroll → Pro-Rata, `/settings/payroll/pro-rata`, Super Admin only; `Settings\ProRataSettingsController` shows and `Settings\UpdateProRataSettingsController` + `UpdateProRataSettingsRequest` saves): the single-row `pro_rata_settings` table (`ProRataSetting`, id + ULID, `current()` = the row or an unsaved one from `defaults()`, no seeder). A part-month wage is the monthly wage ÷ the basis's days × the days paid. `joiner_leaver_basis` (default calendar days, Employment Act s.60I(1C)) and `unpaid_leave_basis` (default fixed days, the ordinary rate of pay) are `App\Enums\ProRataBasis` (calendar days, working days, fixed days); `fixed_days` (20–31, default `STATUTORY_FIXED_DAYS` 26) is null unless a basis uses it (`usesFixedDays()`); `prorate_fixed_allowances`. `daysFor($basis, $month, LeaveSetting $leave)` returns the divisor; working days come from Leave → General's working week with the half working day as 0.5, public holidays not taken out. Fixed rules are shown, not stored: joining and last days are paid, unpaid half days deduct half a day, amounts round to the sen, EPF/SOCSO/EIS use prorated wages. Leave entitlement proration stays on Leave → General. Saves are audited as "Updated pro-rata settings".

**Payslip settings** (Settings → Payroll → Payslip, `/settings/payroll/payslip`, Super Admin only; `Settings\PayslipSettingsController` shows, `Settings\UpdatePayslipSettingsController` + `UpdatePayslipSettingsRequest` saves, `Settings\PreviewPayslipController` streams a sample PDF): the single-row `payslip_settings` table (`PayslipSetting`, id + ULID, `current()` = the row or an unsaved one from `defaults()`, no seeder). Switches (`UpdatePayslipSettingsRequest::SWITCHES`): `show_company_logo`, `show_employer_numbers`, `mask_bank_account`, `show_employer_contributions`, `show_year_to_date`, `show_leave_balance` (off by default), `email_on_release`, `password_protect` (off; the PDF opens with the IC/passport number without dashes). `identity_display` (`App\Enums\PayslipIdentityDisplay`: full, masked = default, hidden), `language` (a `cendana.locales` key, default `en`), `footer_note` (up to `FOOTER_NOTE_MAX_LENGTH` 500, blank saved as null). `displayIdentity()` and `displayBankAccount()` mask all but the last 4 letters/digits, keeping separators. The payslip PDF view is `resources/views/pdf/payslip.blade.php` (inline CSS, DejaVu Sans, company details from `Company::current()`, logo inlined as a data URI); the preview uses saved settings, made-up figures and the payslip language, and the Payroll module will reuse the view with real figures. Saves are audited as "Updated payslip settings".

**Claim settings** (Settings → Claim → General, `/settings/claim/general`, Super Admin only; `Settings\ClaimSettingsController` shows and `Settings\UpdateClaimSettingsController` + `UpdateClaimSettingsRequest` saves): the single-row `claim_settings` table (`ClaimSetting`, id + ULID, `current()` = the row or an unsaved one from `defaults()`, no seeder). Columns: `submission_deadline_days` (0–365 after the expense date, 0 = none; `acceptsExpenseDate($date, $today)` also refuses future dates), `receipt_required_above` (RM, 0 = always; `needsReceipt($amount)`), `allow_resubmission`, `mileage_enabled` + `mileage_rate` (RM/km, null while off), `payment_method` (`App\Enums\ClaimPaymentMethod`: with payroll, using Payroll → General's cut-off day, or separately). Claim types are `LookupCategory::ClaimType` items; per-type limits were left for later. Saves are audited as "Updated claim settings".

**Claim Approval Workflows** (Settings → Claim → Approval Workflows, `/settings/claim/approval`, Super Admin only; `Settings\ClaimApprovalController` lists, `Create/Store/Edit/Update/DestroyClaimApprovalRouteController` + shared `SaveClaimApprovalRouteRequest` manage routes): same model as Leave Approval. `claim_approval_routes` (`ClaimApprovalRoute`, id + ULID, bound as `{claimApprovalRoute}`) holds one route per `applicant_role` plus one default route (null role, can't be deleted). `levels` JSON adds `above` to each level: `{type, value, above}`, where `above` is an RM amount string (2 decimals) or null; a level with an amount is used only for claims above it, and level 1 always applies (`above` prohibited). The form posts `levels[n][approver]` (`role:<Role>`/`user:<id>`, parsed by `SaveLeaveApprovalRouteRequest::parseLevel()`) and `levels[n][above]`; rows without an approver are dropped. `levelsFor($total)` returns the levels a claim goes through; `forRole($role)` falls back to the default. `ClaimApprovalRouteSeeder` (all environments, after `LeaveApprovalRouteSeeder`, never overwrites, no audit) creates the default route approved by role Finance. Audited: "Created/Updated/Deleted claim approval route".

**Hadir (attendance) settings** (Settings → Hadir, Super Admin only; code uses `Attendance…`/`Visit…`, URLs and route names `hadir`). Each page is a single-row table with id + ULID, `current()` = the row or an unsaved one from `defaults()`, no seeder, a show controller plus an `Update…Controller` + `Update…Request`. **General** (`/settings/hadir/general`, `AttendanceSetting`, `attendance_settings`, audited "Updated attendance settings"): `work_start_time`/`work_end_time` stored as `HH:MM` strings (not `time`, so saves don't look dirty) in `cendana.timezone`, `break_minutes` (must be shorter than the day), `late_grace_minutes` (0–60), `missed_clock_out` (`App\Enums\MissedClockOut`), `record_location`, `geofence_enabled` + `AttendanceSetting::GEOFENCE_FIELDS` (`office_latitude`/`office_longitude`, 6 decimals, `geofence_radius_m` 50–5000; null while off; the geofence needs `record_location`), `require_selfie`. Helpers: `workingMinutesPerDay()`, `isLate($clockIn)` (converts to local time), `isWithinGeofence($lat, $lng)` (haversine; true while off). Working days and holidays stay on Leave → General. **Overtime** (`/settings/hadir/overtime`, `AttendanceOvertimeSetting`, `attendance_overtime_settings`, audited "Updated attendance overtime settings"): the time side of overtime; pay rates, eligibility and the monthly limit are on Payroll → Overtime. `capture_method` (`OvertimeCapture`: pre-approval or from clock records), `minimum_minutes` (0–120), `rounding` (`OvertimeRounding`, always down; `minutes()` = block size), `allow_on_rest_days`, `approver_role` (`Role`, required). `countableMinutes($minutes)` applies the minimum then rounds down. **Visits** (`/settings/hadir/visits`, `VisitSetting`, `visit_settings`, audited "Updated visit settings"): work away from the office, checked in/out with location regardless of the geofence. `visits_enabled`, `allowed_roles` (`AsEnumCollection` of `Role`, stored in `Role::cases()` order, at least one while visits are on; Super Admin always allowed and not offered), `counts_as_attendance`, `require_client`, `require_purpose`, `require_photo`, `requires_approval` + `approver_role` (null while off), `suggest_mileage_claim` (the page notes when Claim → General's mileage is off). `allowsAnyOf($roles)` checks the switch and roles.

**Modules** (Administrations → Modules, `/administrations/modules`, Super Admin only; `Administration\ModuleController` lists, `EditModuleController` shows and `UpdateModuleController` + `UpdateModuleRequest` saves; routes take the enum as `{moduleKey}`, e.g. `/administrations/modules/payroll/edit`). The modules are the `App\Enums\ModuleKey` cases (Leave, Payroll, Claim, Hadir; Company and Administrations are always on); add a case, a `ModuleSeeder` Malay name and a navigation `module` key to add one. The `modules` table (`Module`, id + ULID, `key` unique and never changed) holds `name_en`, `name_ms` (null = English, `label()` picks by locale), `icon` (one of `Module::ICONS`, all in the sprite), `sort_order` (1–99), `is_enabled` and `allowed_roles` (`AsEnumCollection` of `Role` in Role order; empty = everyone; Super Admin is always allowed and not offered). `Module::for($key)` returns the row or an unsaved one from `defaults($key)` (on, open to everyone), `Module::registry()` all modules in sidebar order, `isAvailableTo($user)`. Gate a module's routes with the `module:<key>` middleware (`EnsureModuleIsAvailable`, alias in `bootstrap/app.php`): 404 while the module is off, 403 for roles it isn't open to; each module's Settings routes are already grouped behind it, and its future pages must be too. Switching a module off keeps its data. `ModuleSeeder` (all environments, first in `DatabaseSeeder`, never overwrites, no audit) creates every row. Saves are audited ("Created/Updated module").

**Staff records** (`/staff`, sidebar Modules → Staff; `Staff\EmployeeController` lists, `CreateEmployeeController`/`StoreEmployeeController` add, `ShowEmployeeController`, `EditEmployeeController`/`UpdateEmployeeController`, sharing `Staff\SaveEmployeeRequest`; dropdowns from `App\Support\StaffForm::options()`). Open to `Employee::RECORD_MANAGER_ROLES` (Super Admin, Admin, Finance) via `role:` middleware; Staff is always on, not a switchable module. Only Super Admin can give the Super Admin role or edit a Super Admin's record (others can view it). `employees` (`Employee`, id + ULID, never deleted) belongs to a required, unique `user_id`: **every staff member has a login**, and the user's `name`/`email` are their full name and work email; accounts like the seeded admin may have no record (`User::employee()`). Adding staff (a stepped form: Account → Identity → Employment → Pay and statutory → Review) asks only for what HR must know; personal details (gender, race, marital status, children, spouse, phone, personal email, address) and emergency contacts are left for the staff member to fill in later and stay editable by HR on the edit form (`children_count` is only validated when sent, so new records start at 0). It creates the user (random password, chosen role) and record in one transaction, then sends `App\Notifications\StaffAccountCreated` (a "set your password" link using a password-broker token; mail failure doesn't undo the save). Columns: `staff_no` (unique, capitals/digits/dashes), `identity_type` (`IdentityType`: MyKad or passport) + `identity_no` (unique; MyKad stored as 12 digits, shown via `App\Support\MyKad::format()`, and `date_of_birth` is taken from it with `MyKad::birthDate()`; passports need a date of birth; MyKad holders must be Malaysian), `nationality` (one of `App\Support\Countries`, a curated list since production's PHP may lack `intl`), lookup codes `gender`, `race`, `marital_status`, `state`, `department`, `position`, `bank` (new `LookupCategory::Department` and `::Position`; requests accept active codes plus the stored one), `children_count` and `spouse_working` (PCB; kept only when married), contact and address, `employment_type` (`EmploymentType`), `reporting_manager_id` (self-reference; the form posts the manager's ULID), `join_date`, `probation_end_date`, `is_manual_worker`, `last_working_date` + `leaving_reason` (`LeavingReason`; nobody can set their own), `basic_salary` (monthly RM), `bank_account_no` (digits), `epf_no`, `socso_no`, `income_tax_no`, `epf_elected_rate` (only while EPF settings allow it, above the statutory employee rate). Status (`EmployeeStatus`: active, on probation, leaving, left) is worked out from the dates in `cendana.timezone` (`status()`, `withStatus()` scope; the list hides left staff unless filtered). **Leaving blocks sign-in**: `App\Actions\Fortify\RejectStaffWhoHaveLeft` runs before `AttemptToAuthenticate` in the pipeline set by `Fortify::authenticateThrough` (a copy of Fortify's default pipeline; keep it in sync on Fortify upgrades), and `SignOutStaffWhoHaveLeft` (web group) ends existing sessions. Changes are audited ("Created/Updated staff record", salary included). **Emergency contacts** (`emergency_contacts`, `EmergencyContact`, id + ULID): up to `Employee::MAX_EMERGENCY_CONTACTS` (3) per record, edited in fixed rows on the staff edit form (`contacts[n][name|relationship|phone]`; not asked for when adding) and listed on the profile. `relationship` is a `LookupCategory::Relationship` code. Untouched rows are dropped but keep their row index so errors line up; `Employee::syncEmergencyContacts()` updates contacts in place by position, adds new ones and deletes leftovers, so only real changes are audited ("Added/Updated/Removed emergency contact"). **Documents** (profile section `#documents`; `UploadEmployeeDocumentController` + `UploadEmployeeDocumentRequest`, `DownloadEmployeeDocumentController`, `DeleteEmployeeDocumentController`; routes `staff.documents.store|download|destroy` take the media UUID as `{document}`, resolved with `Employee::document($uuid)` so another record's document 404s): Media Library collection `documents` on `Employee` (`HasMedia`), stored on the **private** `Employee::DOCUMENTS_DISK` (`local`, `storage/app/private`), never `public`; files only stream through the download controller (`$media->toResponse()`, attachment). Custom properties `type` (`App\Enums\DocumentType`), `note` (up to `DOCUMENT_NOTE_MAX_LENGTH`), `uploaded_by` (user id). Uploads use `new AllowedUpload` (File Security decides types and size; `media-library.max_file_size` is raised to a 100 MB backstop). Audited against the employee as `document-uploaded`, `document-downloaded` and `document-deleted` (the profile's "Last changed" ignores downloads). `Employee::isEditableBy($actor)` gates changing a record, its contacts and documents (only Super Admin changes a Super Admin's record); every record manager can view and download. Backups include `storage/app/private`. `<x-ui.file-preview>` now checks files against its `accept` list (MIME types, `type/*` or `.ext`). Salary history was left out.

**Auth is real** via Laravel Fortify: `FortifyServiceProvider` registers views (`auth.login`, `auth.forgot-password`, `auth.reset-password`) and the `App\Actions\Fortify\*` actions; login is rate-limited at 5/min per email+IP. **Cloudflare Turnstile** guards sign-in and forgot password: `<x-ui.turnstile />` renders the widget (locale and theme aware) and `App\Http\Middleware\VerifyTurnstile` (in `fortify.middleware`) verifies `cf-turnstile-response` with Cloudflare on `login.store`/`password.email`, failing closed (missing/invalid token or Cloudflare unreachable → back with an `email` error, audited as `bot-check-failed`). Both are inert until `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` (`services.turnstile`) are set, so local and tests skip it; tests enable it with `config()` and `Http::fake()`. Cloudflare's always-pass test keys work locally. All admin pages sit behind `auth` middleware; `/locale`, `/demo/404` and `/testing` are public. The seeder (`DatabaseSeeder`) creates the first admin from `config('cendana.seed_admin')` (`ADMIN_SEED_NAME/EMAIL/PASSWORD`) via `updateOrCreate`; in production it throws without credentials or with a password under 12 chars, locally it falls back to `test@example.com` / `password`.

**Authorization** uses `spatie/laravel-permission` (v8): `User` has the `HasRoles` trait, permissions register on Laravel's gate (`$user->can('edit records')`, `@can`), and the `role`, `permission` and `role_or_permission` middleware aliases are registered in `bootstrap/app.php`. Roles are the `App\Enums\Role` cases (Super Admin, Director, Project Manager, Consultant, Finance, Admin, Staff, Support, Trainee, Sales), created by `RoleSeeder` (called from `DatabaseSeeder`, idempotent); the seeded `ADMIN_SEED_*` admin gets Super Admin. Outside production `RoleUserSeeder` also creates one demo sign-in per other role (`{role-slug}@demo.test` / `password`, e.g. `project-manager@demo.test`); it skips the seeded admin's email and does nothing in production. Super Admin bypasses every check via `Gate::before` in `AppServiceProvider`. No permissions are defined yet and routes aren't role-gated; reference roles through the enum (`$user->hasRole(Role::Finance)`, `'role:'.Role::Finance->value`), never as string literals. Clear `PermissionRegistrar::forgetCachedPermissions()` in tests that create them.

**`config/cendana.php` drives the shell**: branding (from `ADMIN_*` env vars: `ADMIN_NAME` = browser title suffix, `ADMIN_BRAND_NAME`, `ADMIN_WORKSPACE` + `_DESCRIPTION` = sidebar/login, `ADMIN_FOOTER` = footer text), `seed_admin`, `locales`, sidebar `navigation` (groups → items with `route`, `active` route pattern, `icon`, optional `children`), theme accent list and radius options. Adding a page = route + view + navigation entry. `ADMIN_TIMEZONE` (default `Asia/Kuala_Lumpur`) is `cendana.timezone`, the zone pages display times in; `app.timezone` stays UTC for storage, so convert with `->timezone(config('cendana.timezone'))` and turn local date filters into UTC bounds. **Theming**: Tailwind CSS 4 via `@tailwindcss/vite` (no `tailwind.config.js`); design tokens, light/dark themes, accent and radius variables and component classes live in `resources/css/app.css`. **Localization (en default, ms translation)**: `config('cendana.locales')` lists languages; `App\Http\Middleware\SetLocale` (appended to the web group) applies `session('locale')`, set by `POST /locale` (`LocaleController`, route `locale.update`) from `<x-locale.switcher>`. Rules:
- Blade text: write English inside `__()` and add the Malay value to `lang/ms.json` (keyed by the English string). Don't use a key that matches a translation group file name (e.g. `Pagination`) — macOS's case-insensitive FS resolves it to `lang/*/pagination.php` and returns an array.
- Config strings (`navigation` labels, accent/radius names, demo statuses) stay English in `config/cendana.php` and are wrapped in `__()` where rendered, since config loads before the locale is known. Filter/status *keys* (`active`, `draft`, `in-review`…) are untranslated slugs matched by JS `data-status` filters.
- JS strings live in `lang/{en,ms}/js.php`, exposed as `window.__i18n` by `layouts/head.blade.php`; scripts call `__t('key', {placeholder: value})`.
- Inside `@props` defaults use `null` and fill with `@php $x ??= __('...'); @endphp` (block form — inline `@php(...)` breaks when the file also has an `@php` block). Blade's `@json()` splits on commas, so use `{{ json_encode([...]) }}` for array literals in `data-*` attributes.
- In VitePress docs, `{{ }}` inside inline code is evaluated by Vue; wrap such spans in `<span v-pre>`.

**Currency & numbers are Malaysian**: money is MYR (`RM 48.00`, `RM 16.7k`), numbers use dot decimals and comma thousands (`1,284`, `+13.2%`). JS formats with `toLocaleString('ms-MY')`.
